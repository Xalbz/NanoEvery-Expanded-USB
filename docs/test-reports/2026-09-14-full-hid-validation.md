# Full HID hardware validation — 2026-09-14

## Result

**PASS** on the development Nano Every using the Expanded SAMD11 firmware.

The controlled validation sketch in:

```text
examples/Full_HID_Validation/Full_HID_Validation.ino
```

was uploaded normally through Arduino IDE and all three HID paths were observed working on real hardware.

## Tested sequence

The sketch requires explicit single-character commands from Serial Monitor and locks the sequence to `1 -> 2 -> 3`.

### 1 — Gamepad

Duration: 30 seconds.

Observed working:

- HID gamepad remained enumerated in Windows.
- Buttons 1 through 16 were cycled.
- X-axis reports moved between negative and positive values.
- Release reports returned the gamepad to neutral.

Result: **PASS**.

### 2 — Mouse

Duration: 30 seconds.

Observed working:

- Relative X movement.
- Relative Y movement.
- Repeated right/down/left/up movement pattern.
- No mouse clicks were generated by the test.
- Release/stop behavior worked when the stage ended.

Result: **PASS**.

### 3 — Keyboard

Duration: 30 seconds.

Observed working in Windows Notepad:

- lowercase `a-z`
- uppercase `A-Z` using Shift modifier
- number row `0-9`
- Space
- Enter
- Tab
- Backspace
- key release behavior between strokes

The test intentionally avoids Ctrl, Alt, GUI/Windows-key and other potentially disruptive shortcuts.

Result: **PASS**.

## Safe end state

After stage 3, the sketch calls the release-all command and enters a safe idle state. No further gamepad, mouse or keyboard activity is generated. A CDC message is printed periodically:

```text
PING | SAFE IDLE | HID RELEASED
```

## Supporting path

The same Expanded firmware also retains the already verified support path:

- CDC serial
- 1200-baud programming trigger
- JTAG2/UPDI programming to ATmega4809
- normal Arduino IDE `.ino` uploading while Expanded remains installed

## Validation boundary

This test verifies gamepad, mouse and keyboard HID behavior on the development board and Windows host used during development. It does not yet prove cross-board or cross-OS portability. Those remain separate future tests.
